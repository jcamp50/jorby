# Design system and mobile rules (this repo)

**Status:** Implemented in the prototype
**Last updated:** 2026-09-05
**Code:** `apps/web/src/components/ui`, `apps/web/src/components/jorby`

How Jorby should look is [design-direction.md](./design-direction.md). This file is the engineering contract those visuals still have to pass.

## shadcn is real, not imitated

`apps/web/src/components/ui` holds unmodified shadcn `new-york` components generated by the official CLI. Installed so far: `button`, `card`, `input`, `textarea`, `label`, `checkbox`, `tabs`, `badge`, `avatar`, `separator`, `sheet`, `skeleton`, `sonner`. Radix primitives come from the unified `radix-ui` package.

### Adding a component

```bash
cd apps/web && npx shadcn@latest add dialog dropdown-menu
```

The CLI requires **Node >= 22.13**. This project is developed on 22.20; on an older runtime the CLI fails with a confusing `ERR_MODULE_NOT_FOUND` rather than an engine error.

Do not hand-edit files in `src/components/ui`, so `add --overwrite` stays safe. Jorby-specific composition belongs in `src/components/jorby`:

| Component | Purpose |
| --- | --- |
| `MemberMark`, `MemberTag`, `MemberChip` | Member identity: colour plus initials or name |
| `Rating` | Half-star integer to display stars, with a screen-reader text equivalent |
| `PageWash`, `ScreenHeader`, `SectionHeading`, `BackLink` | Page chrome and structure |
| `CardGroup`, `LinkRow`, `Row`, `ButtonRow` | White floating groups and 64px rows |
| `SnapshotRow`, `SnapshotCard` | Horizontal section-count strip (Monzo “pots”, without money) |
| `Tile` | Content-type icon square |
| `HeroCard`, `HeroAction`, `StickyActions` | Saturated hero and thumb-reachable actions |
| `Amount`, `Stat` | Focal numerals |
| `FilterRow`, `FilterChip` | Scrollable full-size filter chips |
| `EmptyState` | Filtered-empty and empty-household messaging |
| `SignedOutShell` | Welcome / chooser / invite on the Home wash |

Theme tokens live in `src/index.css` using the shadcn stone palette in oklch. Dark-mode tokens are defined but nothing toggles `.dark` yet.

## Mobile rules

These are enforced expectations, not aspirations. Every one of them was violated by the first prototype pass.

1. **Touch targets are at least 44px tall.** Includes back links, filter chips, and tab triggers — not just primary buttons.
2. **No horizontal overflow at 320px.** Filter rows scroll horizontally rather than wrapping into cramped rows.
3. **Tab-bar labels are 11px minimum**, with 20px icons in a 56px bar.
4. **Fixed tab bar never covers content.** `main` reserves `calc(3.5rem + env(safe-area-inset-bottom) + 1.5rem)` of bottom padding.
5. **Safe-area insets** are respected on the tab bar; `viewport-fit=cover` is set in `index.html`.
6. **Text inputs render at 16px on small screens** so iOS Safari does not zoom on focus. shadcn's `Input` and `Textarea` already do this via `text-base md:text-sm`; do not override it down to `text-sm` unconditionally.
7. **Primary actions on long forms are sticky** above the tab bar, so Save and Add stay thumb-reachable with the keyboard open.
8. **Destructive or branching choices use a bottom `Sheet`** on mobile rather than an inline block.

### Auditing

`apps/web/e2e/mobile-rules.spec.ts` asserts all eight rules on every route.

```bash
cd apps/web && npm run test:e2e
```

Three Playwright projects run: `mobile-320` and `mobile-390` use WebKit, because iOS Safari is the engine whose quirks these rules exist for; `desktop` uses Chromium and skips the mobile-only rules. Vitest keeps `node` as its environment and excludes `e2e/`, since jsdom computes no layout and cannot check any of this.

## Screen states

Every screen must distinguish initial loading, background refresh, empty household, filtered-empty, not-found or access-denied, recoverable error, and action validation failure.

The mock store simulates the ones that need a backend, via a query parameter:

| URL | State |
| --- | --- |
| `?simulate=slow` | Two-second load, so the skeleton is visible |
| `?simulate=error` | Load failure with a retry affordance |
| `?simulate=empty` | Household with no content, to separate empty from filtered-empty |

Load state resolves once in `AppShell` rather than on each screen. Not-found and access-denied share one `NotFoundState`, so the UI never reveals that another household's record exists.

Actions return an `ActionResult` and surface failures through `toastResult`. Pass a success message only when the outcome is not already visible: a checkbox that ticks needs no toast, but a purchased Thing leaving its lens does. Error copy lives in `lib/errors.ts`, keyed by the normalized error codes from the handoff.

## Known gaps

- No dark-mode toggle, and `theme-color` is light-only.
- Reduced-motion preferences are untested.
- No background-refresh indicator is wired up, though `RefreshingBanner` exists.
- Note locking, provider search, and household switching are still unimplemented.
